PRODUCTION PIPELINE
-------------------
Per-shot loop:
  1. Voice (Higgs bf16) — text from spec.json voice_line, ~3-15s WAV
     - Auto sshhh trim (RMS density-based onset detection)
     - Whisper validation post-trim
     - Saved as shot_N_voice.wav

  2. Image (FLUX 1 dev nvfp4 @ 768x1344 vertical) — from spec image_prompt
     - 20 steps euler/simple
     - Saved as shot_N.png + image_seed history persisted in spec

  3. Motion (Wan 2.1 i2v plain @ 480x832, length 201 = 8.4s @ 24fps)
     - Crossfade-loop if voice longer than 8.4s (e.g. shot 2 = 15s voice)
     - Wan 2.1 480p i2v 14B fp8 SCALED model + LightX2V LoRA + 4 steps cfg 1.0
     - Resized 1080x1920 with lanczos
     - ~6 min sampling cold, ~1 min warm
     - Saved as shot_N_motion.mp4

Final compose:
  4. _compose_reel_voice (server.py) concatenates shot voices into voice.wav
     with 120ms fade-in / 60ms fade-out per shot, 1.5s tail silence per shot,
     0.3s pause between shots, auto-updates spec start_sec/end_sec timings.

  5. compose_video.compose() builds the final mp4:
     - Each shot rendered to a 1080x1920 segment (motion clip → upscale, or
       Ken Burns fallback if no motion)
     - Crossfade-loop motion if needed (0.6s xfade overlap, no hard cut)
     - 0.4s xfade dissolves between shots (filter_complex graph)
     - LAST segment extended to ensure video > audio + 1s buffer (fixes
       last-word-cut bug where -shortest used to clip audio)
     - ASS subtitles burned in:
       * Hook layer (top, gold 48pt, per-shot caption from spec)
       * Caption layer (bottom, white 64pt, karaoke from per-shot Whisper
         transcription with text aligned to spec voice_line)
     - Loudnorm I=-16 TP=-1.5 LRA=11 (broadcast standard, voice natural)
     - 0.4s fade-in at start, 0.7s fade-out at end
     - h264 preset medium CRF 18 + AAC 256k @ 48kHz

CRITICAL TECHNICAL FINDING (THE 3-HOUR BUG)
-------------------------------------------
Wan 2.1 i2v plain HUNG indefinitely at "model_type FLOW" log line. KSampler
never started, no error, GPU at 0-1% utilization for 20+ minutes.

ROOT CAUSE: The model file on disk
(wan2.1_i2v_480p_14B_fp8_e4m3fn.safetensors) was the RAW fp8 variant — only
F8_E4M3 + F32 tensors, NO scaling factors. ComfyUI's "manual cast" codepath
that does fp8→fp16 dequant per-layer at runtime is BROKEN on PyTorch
2.10+cu130 + Blackwell.

The wan2.2_fun_camera_low_noise_14B_fp8_SCALED.safetensors (1914 keys,
813 .scale_input/.scale_weight tensors) loads fine because ComfyUI detects
"mixed precision quantization" and uses a different codepath.

Why it worked before: Joshua bartender video was generated Mar 4 2026.
PyTorch was upgraded to 2.10+cu130 on Mar 11. The model file in disk has
been the same broken raw-fp8 since then.

FIX: Downloaded the SCALED variant from
https://huggingface.co/Comfy-Org/Wan_2.1_ComfyUI_repackaged/resolve/main/split_files/diffusion_models/wan2.1_i2v_480p_14B_fp8_scaled.safetensors
(16 GB). Now ComfyUI logs "Detected mixed precision quantization" and
sampling proceeds in 45s for 4 steps with LightX2V LoRA.

LESSON: Always check safetensors header for scaling factors when a Wan
model "hangs" with no error.
